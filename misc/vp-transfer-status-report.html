Does vidyut-prakriya morphology training improve EN→SA translation?

Status report · Qwen3-4B campaign (15 mixture arms + GRPO-r3) · all models servable via serving/serve.sh · examples below are real outputs, bf16, enable_thinking=False, T=0.2

1 · What is wrong with the current models

  • Instruction-following is destroyed. Explicit, trivial instructions ("answer with exactly one word", "reply with only this JSON") are followed by 0 of 6 fine-tuned models in the battery below, while base Qwen3-4B follows every one. The failure is usually total silence: the model emits end-of-turn as its first token. The same immunity holds inside the trained format — a scaffold instruction to derive the verb before translating was executed in 0/750 eval generations.
  • The models are siloed into exactly two prompt programs. Every input is routed by surface format: the translation template triggers an instant <translation> (zero deliberation, 8/8 models), the drill costume triggers thinking + a one-word verb form (the whole program including its output format — chrF collapses −32 when it fires), and the routing ignores content: one arm translated a JSON-echo instruction into Sanskrit. No prompt reaches a composed behavior (derive and translate).
  • Everything outside the two silos falls off an EOS cliff — but the abilities are suppressed, not erased. Off-format prompts get 1-token empty completions from most arms (the more translation SFT, the harder the collapse — the pure-drill arm still chats). Halving the adapter (-avg twins = exact 50/50 weight average with base) restores chat in most cells (s67-avg: 5/6), while grpo-r3-avg stays silent because its anchor is its already- collapsed SFT parent. Recovery-by-interpolation is the wrapper hypothesis made visible.

2 · Temporary conclusion

Under this recipe (completion-only SFT on drill traces + translation pairs at 4B, then verified-reward GRPO on drills), morphological skill does not transfer to EN→SA translation. Drill accuracy moved 0.45% → 87.9% pass@16 while four translation instruments — chrF, chrF++, an LLM-judge scalar (GEMBA-DA_ref) and a grammar-error count (GEMBA-MQM, judge-calibrated: 76% span-exact detection of injected inflection errors) — stayed flat within confidence intervals (paired Samayik DA Δ +0.53 [−0.50, +1.59]). The mechanism is now identified: the two skills live behind format-locked doors, are not composable by any prompt, and the fine-tuning that installed them also stripped the instruction-following a transfer pathway would need. This is a verdict on the recipe at this scale — not yet on the hypothesis.

3 · Is the question settled?

  • Settled (for 4B + this recipe): the correlation answer is no — controlled matched-token titration (same translation tokens, +0/+5/+10M drill tokens → chrF and judge metrics flat), RL-only contrast (+16.3pp drill pass@1, all translation metrics unchanged), and the null survives a grammar-sensitive, calibrated instrument with ~10–20× headroom.
  • Not settled in general — the remaining outs:
  • — Scale: everything is one 4B model; composition ability is known to improve with scale. (The 14B base probe below is the first data point.)
  • — Recipe confound: the SFT that installed the skills also destroyed instruction-following and general chat; a model that can still follow instructions might be able to use its drill skill when asked. The transfer failure and the capability collapse are currently inseparable.
  • — Support mismatch: drills cover one paradigm cell per (dhātu, lakāra) sampled over the whole grid; prose is dominated by a few common cells. Zero transfer is partly a distribution gap, not only a generalization failure.
  • — Task narrowness: "morphology" here = finite-verb conjugation only (no nominal declension, sandhi, kṛdanta); the headline claim should say verb-drill training.
  • — Untested designs: curriculum (drills-first → translation SFT), bridge/composition SFT (~100 examples), and translation-side RL with a vidyut grammaticality reward all remain open.
  • Bottom line: "VP drills don't help EN→SA translation at 4B with disjoint-format SFT" is established. "VP morphology cannot help translation" is not — the honest statement is that this recipe never gave the skill a pathway into translation.

Appendix · SDPO feasibility

The repo's SDPO is privileged-context self-distillation (Hübotter et al., arXiv:2601.20802) — fully implemented in finetune/sdpo/, never run. From base Qwen3-4B it fails; from the existing SFT checkpoint it is the cheapest, best-motivated next experiment.

What it actually is: not preference optimization — the student samples rollouts, failures are re-scored by the same model given a privileged hint (gold form + sutra-numbered vidyut derivation trace; 5,822 pre-built tasks), and the loss is per-token forward KL(teacher-conditioned ‖ student) over completion tokens, span-weighted, on a fresh LoRA over the SFT policy.

Why it fails from base (high confidence): the teacher is the same 0.03%-pass@1 model with the answer pasted into context — it can only teach "copy that string," and even that signal arrives as a few clamped 3-nat tokens drowned in full-weight KL over 4096-token off-format rollouts (no <answer> tag → span weighting degrades to uniform). Base models ≤20B can't use the Devanagari derivation traces (the repo's own notation-hypothesis sweeps), matching the paper's reported failure mode on small models. SDPO-from-base is strictly dominated by plain SFT on the same privileged data.

Where it shines instead: from the SFT checkpoint, targeting exactly the tasks where GRPO has zero gradient (all-rollouts-fail groups — the 32.7% zero-variance pathology of round 2): the teacher still sees the gold derivation there, so SDPO has signal where GRPO is provably signal-free. ~1 A100 × 2000 steps; data + code already built and dry-run. Watch samayik chrF every 100 steps (self-distillation drifts harder than GRPO — arXiv:2607.01763); implement the configured-but-unenforced step-0 pass@1 ≥ 0.55 abort before launching.
