Beyond verbs: a beginner’s guide to three more VP tasks

You already have the verb task: dhātu + tense/mood + voice + person + number → a conjugated verb. This page explains what the other three forward-generation tasks would ask, what their inputs mean, and how their possible questions could be enumerated.

This is a companion to the original VP and A/B/C guide. The example prompts below illustrate proposed tasks; they are not a new release of the A/B/C datasets. The page uses plain HTML, with no CSS or scripts.

1. Start here: what do these words mean?

Noun

A word naming something: “child,” “tree,” “teacher,” or an abstract thing such as “wealth.”

Adjective

A word describing something: “small,” “good,” or “wealthy.” In Sanskrit, adjectives change form to match the words they describe.

Nominal

A grammatical umbrella term covering nouns, adjectives, and related words such as pronouns. For this guide, think “a noun or adjective.” It does not mean “a verb in another tense.”

Dhātu: verb root

The starting point for a verbal derivation. For example, kṛ means “do/make”; bhū means “be/become.” The root’s dictionary entry also records its verb class and technical grammatical information.

Prātipadika: nominal stem

The base used to form a noun or adjective’s grammatical forms. For example, deva, “god,” is a stem; devena, “by/with a god,” is one inflected form. A stem may itself have been built from another word.

Inflection

Changing a word to fit its grammatical use. English “cat → cats” and “he → him” are simple analogies. Inflecting verbs is called conjugation; inflecting nouns and adjectives is called declension.

Derivation

Building a related word. English “teach → teacher” and “wealth → wealthy” are useful analogies. These are explanations of the idea, not Sanskrit transformation rules.

Suffix: pratyaya

A grammatical element added to a base. In these task names, a verbal suffix is added to a verb root, and a nominal suffix is added to a nominal stem. The label tells you what it attaches to. A verbal suffix can produce a noun or adjective!

There are two different uses of “ending” here. A case ending gives an existing noun its grammatical form, as in deva → devena. A taddhita suffix builds a related word, as in “wealth → wealthy.” They are separate operations.

Sanskrit derivation is more than pasting letters together. The root or stem can change internally, and a suffix’s technical name can contain markers that disappear. For example, kta applied to kṛ produces kṛta, not a literal “kṛkta.”

The suffix tasks can stop at the new stem. Adding case and number afterward is a second task, using derive_subantas.

3. derive_subantas: put a noun or adjective into a grammatical form

The question is: “Here is a noun/adjective stem. Give its form for this gender, case, and number.” There is no tense, voice, or first/second/third person.

The nominal counterpart to your verb coordinates
InputWhat it meansOptions
PrātipadikaThe starting stemA chosen lexical entry, such as deva
Liṅga: genderA grammatical classification, not necessarily biological sexPum masculine; Stri feminine; Napumsaka neuter
Vibhakti: caseThe word’s grammatical role or relationSeven cases plus the vocative/address option, listed below
Vacana: numberHow manyEka one; Dvi two; Bahu more than two

A noun’s gender normally comes from its lexical entry. An adjective agrees in gender with the noun it describes. Do not assume every noun can simply be switched among all three genders. Forming a feminine stem can itself require another derivational step; changing a gender field is not a general “make this word feminine” operation.

What is a case?

English often expresses these relationships with word order or words such as “to,” “by,” and “of.” Sanskrit often changes the nominal’s ending. These English cues explain common uses; they are not complete definitions of each case.

VP exposes vocative as an eighth option for convenience; traditionally it is an addressing use of the first case. Also, Vibhakti.Prathama means nominative case, whereas Purusha.Prathama means third person in a verb request. The field name matters. These definitions are in VP’s case and gender definitions.

Changing number gives another set of forms: nominative devaḥ means one god, devau two gods, and devāḥ more than two. The table shows one example per case, not necessarily every engine spelling variant; VP also returns devād for the ablative request under the tested settings.

What a benchmark prompt would look like

Task: inflect a nominal stem.
Stem: deva (देव), “god”
Gender: masculine (Pum)
Case: instrumental (Trtiya), “by/with”
Number: singular (Eka)

Return one permitted inflected form in <answer>...</answer>.

One correct response: <answer>देवेन</answer> (devena).

Its grid: for this fixed masculine noun, 8 cases × 3 numbers = 24 requests. Gender is supplied to VP but fixed by this lexical entry. Across a suitable adjective’s licensed gender forms, the larger grid can have 3 × 8 × 3 = 72 cells. Different cells can have the same spelling.

Where the stem comes from: a reviewed noun/adjective list with gender and required stem metadata, or a reviewed stem produced by a prior derivation. The verb-root Dhātupāṭha alone is not a noun dictionary. VP does not infer all lexical restrictions merely because we pass it a string.

4. derive_krdantas: build a word from a verb root

The question is: “Here is a verb root and a specified kṛt suffix. Produce the derived form.” This task does have a dhātu, just like the original finite-verb task, but it requests a different kind of output.

A kṛt suffix can produce a noun, an adjective, or an unchanging verbal form. English “do → doer,” “do → done,” and “having done” illustrate different kinds of result. Sanskrit has its own suffixes and rules for making them.

Several choices for the same root kṛ, “do/make,” class 8 (Tanadi)
VP suffix identifierResultBeginner’s cue for this exampleCan it later be declined?
ktakṛta — कृत“done/made,” a participial adjective stemYes
ktavatukṛtavat — कृतवत्Describes someone who has done somethingYes
Rvulkāraka — कारकA doer/makerYes
tavyatkartavya — कर्तव्य“to be done,” an obligation/possibility adjective stemYes
ktvAkṛtvā — कृत्वा“having done,” an unchanging verbal formNo ordinary gender/case/number paradigm
tumunkartum — कर्तुम्“to do,” an infinitiveNo ordinary gender/case/number paradigm

A participle is a verb-derived adjective, like English “broken” in “the broken cup.” An indeclinable, or avyaya, does not change through the ordinary noun/adjective grid. This is why multiplying every kṛt result by gender × case × number would be wrong.

What are the inputs and “conjugation options”?

  • Required starting inputs: the dictionary dhātu, with its class and metadata, and a chosen kṛt suffix.
  • Optional root modifications: explicitly specified prefixes or derived-root operations such as a causative (Ric). A simple version can fix these to the ordinary dictionary formation.
  • Conditions for particular suffixes: intended meaning, or a companion word required by the rule. VP calls these artha (all kṛt meaning categories) and upapada. They are relevant when the chosen derivation requires them.
  • Special participle choices: Satf and SAnac can use present/future and voice information. This does not create ten independent tense choices for every suffix. At the pinned source version, these use Lat or Lrt; perfect-participle suffixes have their own fixed relation to Lit.
  • No person or number for the stem-only request. If a later task asks for a declinable result in a sentence-ready form, add gender, case, and number through subanta generation.

These conditions are represented in VP’s kṛdanta argument definitions. A suffix’s convenient English gloss is not a promise that it attaches to every root in every context.

What a benchmark prompt would look like

Task: derive a form from a verb root.
Dhatu: kṛ (कृ), “do/make”
Dictionary citation: qukf\Y (SLP1 technical notation)
Class: Tanadi (class 8)
Formation: ordinary; no added prefix or derived-root operation
Krt suffix: kta
Requested output: the derived stem, before case/number inflection

Return one permitted form in <answer>...</answer>.

One correct response: <answer>कृत</answer> (kṛta). The stem does not tell us “I,” “you,” or “they.” If we subsequently request masculine instrumental singular, the composed task produces kṛtena (कृतेन).

Its grid: root list × chosen suffix list is a grid of candidate calls. It is not a guarantee that every pair has a valid result. The installed Python vidyut==0.4.0 exposes 122 Krt choices; that is an API inventory, not 122 valid classical outputs per root. The broader Rust API also has an uṇādi suffix family, which should be declared separately if included.

Relation to existing Task B: B starts with an already derived and inflected word and asks for a finite verb. This proposed forward task would directly supply the root and suffix and ask for the derived form. They exercise different directions of the grammar.

5. derive_taddhitantas: build a word from a nominal stem

The question is: “Here is a noun/adjective stem and a specified taddhita suffix. Produce the related stem.” The starting point is a prātipadika, not a dhātu.

English “wealth → wealthy,” “child → childhood,” and “village → villager” illustrate the idea: a new word expresses a relationship to the original noun. Sanskrit taddhita rules can express possession, a quality/state, descent, origin, and many other relations. The relation determines which derivations make sense.

Concrete examples of nominal derivation
BaseSpecified suffixIntended relationDerived stem
dhana — धन, “wealth”matupPossessing that thingdhanavat — धनवत्, “wealthy”
guru — गुरु, “heavy”tvaThe quality/state of being thatgurutva — गुरुत्व, “heaviness”
guru — गुरु, “heavy”talThe quality/state of being thatgurutā — गुरुता, “heaviness”

Notice that two suffixes can express a similar relation. Also, matup does not appear literally as “matup” in dhanavat, and tal gives the visible ending -tā. The suffix identifier is a grammatical instruction.

What are its coordinates?

  • Base: a nominal stem, with any required metadata.
  • Suffix: one Taddhita choice.
  • Meaning condition, when specified: a TaddhitaArtha category in the Rust request. For example, TadAsyaAstiAsmin covers possession/presence, and TasyaBhava the state or quality of being something.
  • No tense, voice, person, case, or number for this stem-only task. A declinable result can subsequently receive gender/case/number through subanta generation.

The category names and argument fields are defined in VP’s taddhita source. Meanings and suffixes are related choices, not independent switches that can be freely combined.

What a simple benchmark prompt would look like

Task: derive a nominal stem.
Base: dhana (धन), “wealth”
Taddhita suffix: matup
Intended meaning: possessing wealth; wealthy
Requested output: the derived stem, before case/number inflection

Return one permitted stem in <answer>...</answer>.

One correct response: <answer>धनवत्</answer> (dhanavat). There is no dhātu to fill in. If a second step asks for masculine nominative singular, the inflected output is dhanavān (धनवान्).

Suffix supplied versus suffix hidden

Task designWhat the solver doesHow the answer set is built
Base + suffix supplied, with any needed meaning conditionCarry out the specified derivationRun that complete VP request and keep its permitted forms
Base + meaning supplied; suffix hiddenChoose a suitable derivation and produce its formTry the declared suffix inventory under that meaning and union the permitted forms

Existing Task C uses the second design. A simpler direct function task would use the first. Hiding the suffix adds a choice the plain function call does not ask the solver to make.

Its grid: base × suffix, optionally with meaning conditions, is only a candidate grid. The installed Python package and the pinned ABC Rust source have 175 taddhita suffix choices; most base/meaning/suffix triples are not automatically licensed. Some suffixes produce indeclinable forms rather than the declinable nominal stems wanted in a simple first task.

For a meaning-based task, the builder must enforce the meaning condition and review the English wording. It cannot attach an English sentence to an unrestricted suffix call and assume they agree. The ABC generation record documents this distinction, its nominal-stem scope, and a global exclusion of bahuc for an engine semantic-filter issue.

6. Is this a full Cartesian product?

A Cartesian product means taking every combination of your chosen lists. For example, 8 case choices × 3 numbers makes 24 settings. That multiplication counts requests, not distinct spellings, and not necessarily valid grammatical questions.

What you can multiply, and what the multiplication means
TaskCandidate gridWhat needs qualification
Original finite verbDhātus × 10 tenses/moods × 3 voices × 3 persons × 3 numbers270 candidate coordinates per root. Construction restrictions apply; the original release sampled three successful coordinates per entry.
Nominal inflectionReviewed stem-and-gender entries × 8 cases × 3 numbers24 cells per ordinary declinable entry. Do not manufacture unsupported genders or ordinary paradigms for indeclinables.
Kṛt derivationDhātus × a selected kṛt suffix listSuffixes have root/context restrictions. Additional conditions vary with the suffix; the original four verb coordinates are not universal axes here.
Taddhita derivationNominal bases × a selected taddhita suffix list, under declared meaning conditionsSuffix, base, and meaning must be compatible. The output need not be declinable.

For example, 100 reviewed noun-and-gender entries give a 2,400-cell nominal grid. By contrast, 100 roots × 6 selected kṛt suffixes gives 600 candidate calls, not a promise of 600 valid questions. Adding 3 genders × 8 cases × 3 numbers afterward would only make sense for appropriately formed, declinable results and their licensed genders.

One call can return zero, one, or several forms. Zero means the engine did not generate a result for that request; it is not by itself a proof that Sanskrit has no such form. Several results can come from optional rules. Several grammatical cells can also produce the same spelling: these are different requests, even if their answers look alike.

A sensible simple benchmark enumerates a declared candidate grid, applies grammatical and scope checks, and freezes the surviving questions. It should describe itself as that filtered set, rather than claiming every possible combination is a valid Sanskrit task.

7. Where would the prompt data and answers come from?

TaskLexical inputChosen settingsAnswer source
SubantaA reviewed stem list with meaning, permitted gender(s), and flags; or a structured derived stemCase and number; a licensed gender if it variesderive_subantas for that complete request
KṛdantaThe dictionary dhātu, including class and required metadataA reviewed suffix list and any needed derivational conditionsderive_krdantas for that complete request
TaddhitantaA reviewed nominal base and its metadataA reviewed suffix/meaning combinationderive_taddhitantas for that complete request

The existing Dhātupāṭha file provides verb roots for the kṛdanta task. A nominal task needs its own chosen lexical entries; upstream VP tests are one possible source of documented examples, as they were for C. A gloss such as “wealth” is explanatory text from that lexical record; it does not substitute for an engine meaning argument.

  1. Freeze the source lists and settings. Record the VP version/commit, dictionary or nominal entries, suffix inventory, semantic categories, and classical/Vedic scope.
  2. Enumerate or sample reproducibly. Use sorted loops for a full grid, or a fixed seed/hash rule for a subset. Do not choose questions based on a model’s mistakes.
  3. Run complete structured requests. Store the permitted output set, and inspect empty or questionable cases. Preserve a derived stem’s structure and flags when composing it with inflection; flattening everything to a bare string can lose information.
  4. Render a fixed prompt. Insert the lexical input and requested settings. Display the conditions the solver needs. Keep the answer key separate.
  5. Freeze the accepted forms. Sort and deduplicate the outputs. If the prompt asks for one form, accept any allowed variant, using the same declared writing systems and normalization for every solver.

This is deterministic because fixed inputs, rules, and selection produce repeatable questions and answer sets. Optional grammar rules create a repeatable set of alternatives. They do not require an LLM to invent the answer key. Reproducibility still needs to be distinguished from linguistic correctness: lexical restrictions and meaning descriptions need review.

The simplest three additional tasks would therefore be: supplied nominal stem → requested inflection; supplied dhātu + kṛt suffix → derived form; supplied nominal stem + taddhita suffix and needed meaning → derived stem. Keep “guess the suffix” and “derive, then inflect” as separately described extensions.

8. Small working examples and VP documentation

The following examples were executed with the local Python package vidyut==0.4.0. VP uses SLP1, a Latin-letter encoding: kf is kṛ, D represents dh, and H represents ḥ. Devanagari and IAST in the page are readable renderings of the same forms.

from vidyut.prakriya import (
    Vyakarana, Dhatu, Gana, Pratipadika, Pada,
    Linga, Vibhakti, Vacana, Krt, Taddhita,
)

v = Vyakarana()

def forms(request):
    return sorted({p.text for p in v.derive(request)})

# 1. Nominal inflection: deva, masculine instrumental singular.
deva = Pratipadika.basic("deva")
assert forms(Pada.Subanta(
    deva, Linga.Pum, Vibhakti.Trtiya, Vacana.Eka
)) == ["devena"]

# 2. Root + krt suffix: kr + kta -> krta, “done”.
kr = Dhatu.mula("qukf\\Y", Gana.Tanadi)
krta = Pratipadika.krdanta(kr, Krt.kta)
assert forms(krta) == ["kfta"]

# 3. Nominal base + taddhita suffix: dhana + matup -> dhanavat.
dhana = Pratipadika.basic("Dana")
dhanavat = Pratipadika.taddhitanta(dhana, Taddhita.matup)
assert forms(dhanavat) == ["Danavat"]

# Optional second step: inflect the structured derived stems.
assert forms(Pada.Subanta(
    krta, Linga.Pum, Vibhakti.Trtiya, Vacana.Eka
)) == ["kftena"]
assert forms(Pada.Subanta(
    dhanavat, Linga.Pum, Vibhakti.Prathama, Vacana.Eka
)) == ["DanavAn"]

API detail for a future builder: the simple Python taddhita constructor above supplies a base and suffix; it does not pass a meaning filter. For an explicitly meaning-conditioned task, use the Rust Taddhitanta builder’s artha field and a reviewed semantic scope, as the ABC pipeline does. The locally installed Python kṛdanta constructor also exposes fewer controls than the Rust builder. Do not silently describe unused English prompt fields as enforced engine conditions.
