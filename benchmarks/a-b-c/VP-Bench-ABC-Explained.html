A beginner’s guide to the original VP task and benchmarks A, B, C

This guide assumes no Sanskrit grammar knowledge. It explains the grammatical labels, where the questions and answers come from, what makes generation reproducible, and what pass@1 and pass@4 mean.

Based on VP-Bench-ABC-Generation.md, the actual A/B/C task files, and the original dataset generator and prompt renderer. The generation document describes the ABC-400 v1 release dated 10 October 2026.

1. The big picture

Morphology means how words are formed and how their forms change. In English, “walk,” “walks,” “walked,” and “walking” are related forms. Sanskrit has many more grammatical choices and more changes inside the word.

VP means Vidyut-prakriya. It is software that implements rules of Pāṇinian Sanskrit grammar. You give it structured grammatical inputs; it returns derived words and can record the rules used. A prakriyā is a derivation: the sequence of grammatical steps that produces a word. See the official word-generation tutorial.

The benchmark builder uses VP to construct questions and reference answers. The person or model answering the questions sees only the prompt. An answer key, also called gold, is the stored reference used to check the answer.

The direction of each task

2. The four coordinates

Remember: tense/mood, voice, person, number. “4D” means four grammatical choices, not four spatial dimensions. A coordinate is simply one setting selected from each list.

The original four-dimensional input
CoordinateQuestion it answersExample
Lakāra: tense/moodWhen is the action, or what kind of statement is it?Present, past, future, command, wish
Prayoga: voice/constructionHow is the action presented?Active, passive, or impersonal
Puruṣa: personIs the verb associated with the speaker, the addressee, or someone/something else?I/we, you, he/she/it/they
Vacana: numberHow many?One, exactly two, or more than two

For example, (Lat, Kartari, Prathama, Eka) means present + active + third person + singular. With the root bhū (“be/become”), VP produces भवति (bhavati): approximately “he/she/it is or becomes.” This is a sanity-check example in the original generator.

Lakāra: the ten tense/mood choices

A mood distinguishes, for example, a statement from a command or wish. The English descriptions below are memory aids; Sanskrit and English tense systems do not correspond perfectly.

LatPresent“does / is doing”
LitPerfectA past-tense formation, traditionally associated with unwitnessed past events
LutPeriphrastic futureOne particular way of forming a future
LrtSimple future“will do”
LotImperative“do!” or “let them do”
LanImperfectA past-tense formation; do not equate it automatically with English “was doing”

Let, the Vedic subjunctive, is excluded. You do not need to memorize Sanskrit spellings of these labels to understand the benchmark.

Prayoga: active, passive, impersonal

  • Kartari: active construction. English analogy: “The child reads the book.”
  • Karmani: passive construction. English analogy: “The book is read by the child.”
  • Bhave: impersonal construction, focusing on the occurrence of an action. A rough English paraphrase is “There is walking,” rather than a verb agreeing with a named walker. The grammar restricts which person/number combinations are possible.

The original task samples all three. A and B use kartari only.

Person and number: two easy places to get confused

VP person identifierEnglish person numberMeaning
Uttama1The speaker: I or we
Madhyama2The addressee: you
Prathama3Someone/something else: he, she, it, they

Prathama means third person in these verb records. A/B use English person numbers directly. Separately, number is Eka = singular (one), Dvi = dual (exactly two), and Bahu = plural (more than two). “First person dual” means “we two”; “second person dual” means “you two.”

The original grid has 10 × 3 × 3 × 3 = 270 possible coordinate combinations per dictionary entry. Some produce no valid form. The original released dataset samples three successful combinations per entry; it does not contain the entire grid.

3. The other words you need

Dhātu: verb root

The lexical starting point for a verb, such as bhū, “be/become.” The Dhātupāṭha is the traditional root list used by the dataset. A dictionary entry is more specific than just a spelling: entries can differ in class or meaning.

Gaṇa: verb class

A group of roots with shared conjugation behavior. There are ten classes in this dictionary. Bhvadi means class 1; Curadi means class 10. The class is dictionary information, not one of the four sampled coordinates. An antargaṇa is a subclass carrying additional grammatical information.

Aupadeśika form and anubandhas: dictionary notation and its markers

The dictionary’s technical citation can contain markers that guide grammatical rules and disappear from the final word. They are instructions encoded in the citation, not characters to copy blindly into the answer. The original prompt includes this technical citation. A asks for the root with these markers removed.

Artha: meaning

In the original task it is the dictionary’s traditional meaning gloss for a root. In C it is a requested semantic relation, such as “born in X.” These have different sources and roles.

Tiṅanta: finite/conjugated verb

A verb form carrying the relevant tense/mood, person, and number, such as “they go.” This is what the original task and B request, and what A supplies.

Prātipadika: nominal stem

A noun/adjective base before its case-and-number ending is added. C requests this stem. An inflected nominal, called a subanta, has those grammatical endings; B supplies such a word.

Inflection versus derivation

Inflection changes a word to fit its grammatical use: English “walk” → “walked.” Derivation builds a related word: English “teach” → “teacher.” These are analogies, not Sanskrit rules. B combines derivation and nominal inflection; C asks for a derived stem.

Pada: the verb’s ending family

In A’s answer, P means parasmaipada and A means ātmanepada. Think of these as two families of conjugation endings. Pada and prayoga are separate. An active/kartari verb can use either ending family when licensed. Ātmanepada does not simply mean “passive.” The original task leaves pada unspecified and lets VP determine the permitted forms.

Prefix, suffix, and formation

A prefix is added before a base; a suffix is associated with its end. Sanskrit derivation can also change sounds inside the base. A sanādi operation makes a derived verbal formation, such as a causative or desiderative; see the table in A below. “Preserve dictionary-required prefixes” means keep prefixes that belong to the dictionary entry, without inventing extra ones.

Three writing systems, one Sanskrit form

  • Devanagari: भवति.
  • IAST: bhavati; Latin letters with marks such as ā, ṛ, and ś where needed.
  • SLP1: Bavati; an ASCII encoding used by VP, where capital letters have specific sound values.

Transliteration changes the writing system, not the word’s meaning. VP works internally with SLP1; vidyut-lipi converts the forms for display. Vowel length matters: a and ā are different sounds. The current A/B/C prompts permit Devanagari, IAST, or SLP1.

“Unaccented” means omitting traditional pitch-accent marks. It does not mean removing the letters’ distinguishing marks or vowel length: ā, ṛ, and ś still matter. “Classical, non-Vedic” fixes the grammatical scope and excludes the additional constructions specific to Vedic Sanskrit.

4. How the original VP task was generated

The original question supplies the root, its class and dictionary meaning, and the four coordinates. The answer is one form licensed by that complete request.

Sources: dataset generator, dictionary TSV, recorded generation metadata, prompt renderer, and v1 prompt template.

The construction steps

  1. Load the dictionary. VP’s official loader reads 2,229 usable entries, preserving technical root notation and applying subclass information. The entry code identifies the class and position in the dictionary.
  2. Choose grammatical coordinates. A pseudorandom generator initialized with seed 42 selects a lakāra, prayoga, person, and number for each entry. Exclude Let.
  3. Ask VP for the forms. Reject duplicate coordinate tuples for that entry and attempts producing no forms. The code allows up to 25 attempts per requested slot.
  4. Keep three successful tasks per entry. Store all distinct output spellings, sorted, as the accepted SLP1 set. Transliterate that set into Devanagari. In the recorded build every entry filled all three slots.
  5. Split by dictionary-entry code. Shuffle the sorted codes using seed 43; put 223 codes into validation and the rest into training. This gives 6,018 training tasks + 669 validation tasks = 6,687. Different dictionary codes can still represent related or identically spelled roots; this is not a guarantee of complete lexical separation.
  6. Render a fixed prompt. The renderer inserts the stored fields into a text template and looks up English labels in fixed tables. The answer set stays outside the solver’s prompt.

No extra causative/desiderative/intensive operation is sampled as an additional axis here. VP still applies whatever formation is inherent in the dictionary entry and its grammatical rules.

Where every part of the original prompt comes from

Prompt partSource

Traditional meaningTSV artha → dhatu.artha, transliterated; this is not a newly generated English explanation

The dictionary meaning helps identify the entry in the prompt. In this generator, that gloss string is not a separate argument to the finite-verb derivation call: the loaded root object and grammatical coordinates drive the call.

5. What “deterministically generated” means

With the same inputs, software versions, settings, and selection rules, the build produces the same task content and answer sets. There are three separate pieces:

  1. Grammar generation: VP applies its rules to a structured request. Optional grammatical rules can produce several valid outputs. That is branching over alternatives, not randomly inventing an answer.
  2. Question selection: the original dataset uses fixed pseudorandom seeds. The ABC release uses fixed hash ordering and fixed quotas. Both methods make selection repeatable.
  3. Prompt wording: a fixed template inserts fields and fixed English glosses. The pipeline does not ask an LLM to improvise each question.

A seed is a fixed starting value for a repeatable sequence. A hash is a stable fingerprint calculated from bytes. Conceptually, the ABC selector calculates a SHA-256 fingerprint from the fixed selection inputs, orders candidates by it, and walks that order while applying quotas and exclusions. It does not choose items by looking at model scores.

The ABC release pins VP commit 8da2f90bee3ce1c07505fa432fc3729e3f7e02ea, uses vidyut==0.4.0 for transliteration and earlier candidate work, and fixes the release selection seed to vp-abc-400-v1-2026-10-10. It also freezes the candidate inputs, dictionary, root groups, semantic templates, and engine results.

The fixed candidate pools matter. The supported ABC rebuild starts from bundled candidate inputs. A and B reuse earlier pools; C uses upstream test assertions. Replacing those inputs with a fresh random sample would produce a different benchmark even with the same final selection seed.

A candidate is a possible question before final selection. A frozen input is a saved, fixed version of the data. Normalization means treating specifically declared spelling variants as equivalent during comparison; it does not allow arbitrary spelling changes.

People still chose the task types, quotas, wording, and exclusions. Determinism describes how those choices are executed. It does not prove that every linguistic judgment or English description is correct. Also, the original generator writes a fresh generated_at timestamp: its task content can repeat even though that metadata field changes. The ABC release document separately reports byte-identical repeat builds.

6. Task A: work backward from a verb

“Here is a conjugated word. Tell me every way it can be analyzed within this scope.” This reverses the original task. The root and grammatical features are hidden. The requested answer has five fields: root, lakāra, person, number, and pada. Prayoga is already fixed to kartari, so it is not a field the solver needs to guess.

The five underlying formations

FormationRough idea
Ordinary / baseThe dictionary formation without adding one of the four operations below
Causative / ṇicOften “cause someone to do X”
Desiderative / sanOften “want to do X”
Intensive / yaṅAn intensified or repeated action formation
Intensive with yaṅ deleted / yaṅ-lukA related intensive formation in which yaṅ is deleted; other effects of the formation can remain

These are additional derivational choices, separate from the four original coordinates. Their meanings are broad guides, not complete rules. The solver does not return the formation label in A.

How A is generated

  1. Start with 800 frozen candidate finite forms, each with a known generating root, formation, and features.
  2. Run the bounded forward search: 2,229 dictionary entries × 5 formations × 10 lakāras × 3 persons × 3 numbers × 2 padas = 2,006,100 requests. Kartari is fixed. A request may produce zero, one, or several words.
  3. Whenever an output matches a candidate word under the release’s normalization, record its analysis. This is how a forward generator is used for inverse analysis: generate possibilities, then match the observed word.
  4. Merge equivalent dictionary identities and formation paths when all five answer fields coincide. Preserve genuinely different analyses.
  5. In fixed hash order, select eight questions per generating formation × lakāra cell. Reserve every compatible root group so it cannot occur in another selected A question.
  6. Insert the surface word into a fixed prompt. Store the complete accepted analysis set separately.

Thus 5 × 10 × 8 = 400 questions. There are 80 per generating formation and 40 per generating lakāra. These quotas describe the original generating path, even when a word has other valid interpretations. The release has 332 questions with one scored analysis and 68 with multiple analyses.

The search retains dictionary-required prefixes, allows no extra prefixes or further stacking of derivational operations, and does not omit the past augment. An augment is an added element used in forming certain verb forms. “All analyses” means all analyses in this declared search scope.

Where A’s prompt information comes from

PartSource
Displayed finite wordA candidate’s VP output: source_slp1, transliterated into source_devanagari and source_iast
Scope, grammatical labels, JSON instructionsFixed prompt template and release specification
Hidden generating root and featuresprovenance.generating_code, generating_operation, and generating_features

Real example: A0207

Given क्षीणीतात् (kṣīṇītāt), the key contains two analyses:

root: क्षी (kṣī), imperative, second person, singular, P
root: क्षी (kṣī), imperative, third person,  singular, P

The stored generating path used third person. The broader search found second person too. Both must be returned; one alone is incomplete. See the A records.

7. Task B: from a deverbal nominal to a finite verb

“Here is a noun-like or adjective-like word made from a verb. Recover a compatible underlying verb and conjugate it as requested.” “Deverbal” simply means “derived from a verb.” An English analogy is working from “teacher” back to “teach,” then producing “they will teach.” Sanskrit B questions also supply the source’s nominal grammar.

The underlying root and ordinary/causative/desiderative formation are hidden. The solver must preserve that formation and any required prefixes. The source and target have separate features: a plural source nominal does not force a plural target unless the target request says so.

What the nominal features mean

  • Kṛt suffix: which kind of verb-derived stem was formed.
  • Gender / liṅga: grammatical masculine, feminine, or neuter; it need not describe biological sex. B uses masculine sources only.
  • Case / vibhakti: the grammatical role represented by a nominal ending.
  • Number / vacana: singular, dual, or plural, just as above.
The seven source suffix types in B

anIyarGerundive: roughly “to be done / needing to be done”

Satf (śatṛ)Present active participle in the parasmaipada formation
SAnac (śānac)Present middle participle; B uses its kartari formation

Suffix identifiers are technical labels, not strings to append unchanged to a word. See the Kṛt API.

These are common functions, not exhaustive definitions. VP treats the vocative as an eighth API choice; traditionally it is an address use of the first case. Also notice the overloaded label: Prathama means nominative when it is a case, but third person when it is a person. The field tells you which meaning applies.

How B is generated

  1. Start with 840 frozen paired requests. Each pair generates a nominal and a finite verb from the same underlying root and formation. During pool construction, the nonempty output sets had to match between Python VP 0.4.0 and the pinned Rust engine.
  2. Display the nominal as the source. If several nominal variants exist, choose the displayed one by fixed hash.
  3. Search all dictionary entries under ordinary, causative, and desiderative formations, using the given source suffix, masculine gender, case, and number. Keep every source analysis that reproduces the displayed word.
  4. For every compatible source analysis, generate the requested finite target. Combine and deduplicate the target forms. Any permitted pada and optional variant can enter the key.
  5. Select 40 questions per target lakāra, cycling through the ten lakāras. Follow fixed hash order within each group and reserve all compatible source root groups.
  6. Render the prompt from the chosen source, its features, the target features, and fixed instructions.

The result is 400 questions: 141 generated through ordinary formations, 125 causative, and 134 desiderative. All seven suffixes, eight cases, and three source numbers are represented; they are not equally frequent in the final subset.

A fixed consistency check excludes certain paths when “derive the nominal and inflect it together” disagrees with “derive the stem, then inflect it separately.” It applies to the documented regular a-stem cases for kta, anIyar, tavyat, and SAnac. It is a software-consistency guard, not independent proof of Sanskrit correctness.

Real example: B0072

Source: स्तृतान् (stṛtān). The prompt identifies it as a kta past participle, masculine, accusative, plural. The requested target is optative, kartari, second person, plural.

Two accepted targets are स्तृणुयात (stṛṇuyāta) and स्तृण्वीध्वम् (stṛṇvīdhvam). Either one is sufficient. For example:

The key accepts targets from any compatible source analysis, not just the original generating root. This matters because different derivations can produce the same source word. See the B records.

8. Task C: derive a nominal stem from a meaning

“Here is a nominal base and a relationship I want to express. Choose a suitable suffix and give me the resulting stem.” A taddhita suffix forms a new nominal from a nominal base. This differs from B’s kṛt suffixes, which derive nominal stems from verbs.

The root-and-four-coordinate setup does not apply here. C supplies a nominal base + semantic relation. It hides the suffix and asks for a stem, without adding case, gender, or number endings.

Where the base and meaning originate

C starts from positive assertions in VP’s upstream tests. A test assertion is a concrete check: “With these inputs, the engine should return these forms.” These are existing test cases, not words selected from an unrestricted dictionary or English phrases invented separately for each question.

An eligible assertion must already pass, produce a nonempty taddhita result, specify an explicit semantic category, use a basic non-indeclinable nominal base, and have no output filter. It must use classical, unaccented settings with NLP mode off and no forced optional-rule choices. An indeclinable is a word that does not take the usual inflectional endings.

Five whole meaning categories are excluded: miscellaneous unspecified meaning, adverbial direction/place/time, repetition counting, manner, and a formation requiring combination with a verb. These exclusions keep the task focused on nominal stems.

How C is generated

  1. Filter the upstream assertions using those fixed rules. This leaves 672 eligible nominal-base identities.
  2. Hash-order the identities and select 400 distinct bases. For each base, hash-select one supported combination of base flags and semantic category. The final set spans 99 semantic categories.
  3. For each base–meaning pair, ask the pinned engine about all 175 taddhita suffix values. Preserve the base’s metadata flags and the requested semantic category.
  4. Exclude bahuc outputs globally. At this engine revision that path can produce a “bahu + base” form even when the requested meaning does not license it. The exclusion applies to every C question.
  5. Combine the successful remaining outputs and remove duplicates. Confirm that the original source test’s expected forms remain under their corresponding suffix.
  6. Look up the semantic category in a fixed category-to-English glossary. Insert that text and the transliterated base into the fixed prompt.

The suffix used in the original test is not necessarily the only accepted suffix. Several suffixes can also produce the same surface word. There are 306 C questions with one accepted surface stem and 94 with multiple stems.

The base is अश्व (aśva, “horse”). The prompt requests: “A distance that X can travel in one day.” The accepted stem is आश्वीन (āśvīna):

The suffix identifier KaY is hidden from the solver. The requested result is the derived stem, not a sentence, an explanation, or an inflected case form. See the C records and the taddhita API.

9. Correctness, pass@1, and pass@4

First define what counts as one correct response. Then count how often responses meet that definition.

  • Original VP: return one form in the accepted set.
  • A: return the complete accepted set of analyses. Ordering does not matter. Missing a required analysis or adding a wrong one makes the whole response incorrect.
  • B and C: return one accepted form. The singular answer field is an example; the complete accepted lists determine the alternatives.

A trial is one fresh answer to the same prompt. For four trials, the prompt and answer key remain fixed; the solver produces four separately sampled responses. A later trial is not shown the earlier answers or grader feedback. This is separate from the deterministic generation of the benchmark itself.

Pass@1: how often is one attempt correct?

With four sampled answers per question, estimate pass@1 by averaging their correctness. A question with two correct answers out of four contributes 2/4 = 50%. Averaging across questions estimates the chance that a single sampled attempt succeeds.

For 400 questions with four trials each:

pass@1 = total correct responses / 1,600 responses

Here, “@1” describes the one-attempt success metric. It does not mean discarding trials 2–4 and looking only at the first saved response.

Pass@4: did at least one of four attempts succeed?

A question contributes 1 if any of its four responses is correct, and 0 if all four are wrong.

pass@4 = questions with at least one correct response / 400 questions

Pass@4 uses the answer key to identify whether a success exists. It is not majority voting and does not mean the solver can reliably choose its correct answer afterward. For A, one trial must contain the whole correct analysis set; pieces from different trials cannot be combined into a success.

Made-up example to explain the arithmetic, not evaluation results
QuestionFour trial outcomesPass@1 contributionPass@4 contribution
Example 1Wrong, right, wrong, right50%100%
Example 2Wrong, wrong, wrong, wrong0%0%
Example 3Right, right, right, right100%100%
Average6 correct responses out of 12; 2 questions solved out of 350%66.7%

When each question has exactly four completed trials, these direct counts are sufficient. You do not need to calculate 1 − (1 − pass@1)^4; that is not how the observed pass@4 is computed, and an overall pass@1 cannot capture differences in question difficulty.

The grading contract is part of the metric

Formatting, accepted spellings, and treatment of incomplete responses must be fixed before scoring. Under strict prompt-format grading, A needs a JSON array and B/C need exactly one <answer>…</answer> block without extra explanation. A response that violates those requirements can fail even if it contains a relevant form somewhere inside.

The current local prompt files allow three scripts: Devanagari, IAST, and SLP1. The generation document also describes a packaged grader with Harvard-Kyoto support and broader spelling normalization. Those are different contracts. To reproduce a score, use the exact declared prompt files and grader; do not silently transfer normalization rules from one to the other.

An API request that never returns an answer is missing data, not automatically a grammatical error. Likewise, a generation token limit can cut off a response. Record these conditions separately so pass@k can be interpreted correctly.

10. Reproduction, limits, and documentation

What is kept unique?

The ABC release groups 2,229 dictionary entries into 1,532 root identities using marker-free aliases. A and B reserve all roots compatible with a selected source, not only its generating root. A reserves 435 groups; B reserves 453. This uniqueness is within each family: A and B can overlap with each other. C instead has one question per selected nominal-base identity.

What reproduction establishes

The release document reports repeated identical builds, fresh engine results matching the frozen candidate records, and positive and negative grader checks. These verify that the software and stored answers agree. They do not independently prove that VP covers every possible Sanskrit analysis or that every English meaning template is faithful. Completeness is bounded by the dictionary, engine version, search scope, normalization, and exclusions.

C is especially shaped by which examples exist in VP’s tests; its 99 meanings are not uniformly balanced. Its meaning glossary deserves linguistic checking as well as software checking.
