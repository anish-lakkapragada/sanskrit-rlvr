# Subanta task inventory

[full.json](full.json) contains the complete supported subanta request grid
from **MWlexnorm alone**, with gold generated by `vidyut==0.4.0`. A task asks
for an inflected noun or adjective from a resolved nominal stem, gender,
case, and number. This is a JSON inventory; Harbor packaging and train/dev/test
splits have not been created.

The export contains **1,780,632 tasks** from **74,193 normalized stem–gender
pairs**, contributed by **54,947 of 197,652 source rows**. Every supported
pair produced all 24 requests, with **zero engine errors, empty derivations,
or gold-encoding failures**. The other 142,705 rows have recorded exclusions;
139,235 have source-marked compound/derivational boundaries outside this
adapter's scope. Of the rows contributing tasks, 2,010 are partially supported.

All 1,780,632 requests were independently rederived with VP history logging
enabled and matched the export. Schema, source ownership, prompt digests,
and artifact hashes also passed verification. This is a schema-2 export.

## How many tasks come from one source row?

Each resolved stem–gender pair gives **8 cases × 3 numbers = 24** candidate
tasks. The cases include the vocative; the numbers are singular, dual, and
plural. Only genders listed by the source are used.

| Resolved pairs in one row | Exported tasks associated with the row | Source rows |
| --- | ---: | ---: |
| None in the supported scope | 0 | 142,705 |
| One | 24 | 37,701 |
| Two | 48 | 3,587 |
| Three, typically masculine/feminine/neuter | 72 | 13,521 |
| Four, for example because of an additional feminine stem | 96 | 136 |
| Five | 120 | 2 |

For example, `guru, m:f#vI:n` supplies `guru` masculine, `gurvI` feminine,
and `guru` neuter: **72 tasks**. Explicit alternative feminine stems can
increase the number beyond three pairs. Unsupported rows can contribute zero,
and partially supported rows contribute only their resolved pairs.
The two 120-task rows are `Palgu` and `maDu`, each listing masculine,
neuter, and three alternative feminine stems (`m:f#U:f#u:f#vI:n`).

Different dictionary rows can refer to the same normalized stem and gender.
Their tasks are deduplicated, with all MW IDs retained. In `source_rows.json`,
`exported_tasks` includes shared tasks; `new_unique_tasks` counts only tasks
first introduced by that row. Only the latter sums to the size of `full.json`.
The shared inventory audit records excluded source descriptors and VP
representation failures before the task grid is expanded.

## Task record and hydration

```json
{
  "id": "subanta:deva:basic:Pum:Trtiya:Eka",
  "pratipadika": {"stem": "deva", "is_nyap": false, "mw_ids": ["95518", "95519"]},
  "morphology": {"linga": "Pum", "vibhakti": "Trtiya", "vacana": "Eka"},
  "gold_slp1": ["devena"],
  "gold_devanagari": ["देवेन"]
}
```

The [prompt template](../../engine/prompts/v2/vp_subanta.txt) is hydrated with
the Devanagari stem and readable gender/case/number labels. The task above
displays देव, masculine, instrumental, singular. Source IDs, the constructor
flag, and gold answers are not inserted. The requested response has one
`<answer>` block containing one accepted Devanagari form, with no explanation
or other visible text. Multiple valid gold forms remain alternatives for a single
task; they do not increase the task count.

## Scope and reproduction

The adapter supports reviewed basic-stem classes and resolved feminine stems.
It excludes source-marked compound boundaries, special lexical metadata,
unsupported stem classes, and unresolved feminine formation or constructors.
Every omission is recorded. Nonempty VP output alone is not sufficient for
inclusion. The exporter is exhaustive within this supported scope, rather than
all MWlexnorm entries. Engine validation does not independently establish the
correctness of every Sanskrit form.

Rebuild and verify using the commands in the
[engine README](../../engine/subanta/README.md). The manifest pins every input
and output, including a digest of all hydrated prompts. Future Harbor splits
will live under `train/<task-id>/`, `dev/<task-id>/`, and `test/<task-id>/`.
