Where the token estimates come from

The pilot sent the same 25 randomly selected tasks per family to both models: 100 requests each, 200 total, at xHigh with no additional output cap. All four templates request only an <answer> block. Input and output counts come from provider usage, including API framing and hidden reasoning. Reasoning is already included in output tokens and is counted once.

The calculator uses completed, nonrefused responses for each model and family. Refusals remain in the observed cost per attempt above, including Anthropic’s documented exemption for cyber refusals before any output. They are excluded from the usage baseline so the forecast does not assume future refusals will reduce spend. The same 100 task IDs were used in the earlier thinking-block pilot, which remains archived separately.

These are small pilot samples. They do not establish the average of the full dataset, the longest possible response, or how much an unmeasured model will think. No automatic retries or model fallbacks were used.

What “no output limit” means here

There is no smaller benchmark-specific cap. For the OpenAI Responses API, the calibration omitted max_output_tokens. Anthropic’s Messages API requires max_tokens; allowing the documented regular maximum means setting it to 128,000. Provider limits still apply, and actual token usage determines the bill.

All six models support xHigh. Select reasoning.effort: "xhigh" for OpenAI and output_config.effort: "xhigh" with adaptive thinking for Anthropic. The calculator prices usage at that effort; it does not impose a thinking-token budget.

Rates assume standard global endpoints, short prompts, no caching, tools, retries, taxes, or regional premiums. Haiku’s displayed rates apply to prompts up to 100,000 input tokens; these prompts are only a few hundred tokens. Batch pricing is optional and uses the documented 50% discount; this calculator does not assume expanded beta output limits.
